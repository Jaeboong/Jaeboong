# TODO 앱 AI 인프라 어시스턴트 (DoitDo)

> 인프라 담당자에게 집중된 서버 점검·로그 분석·데이터 확인·장애 대응 업무를 팀이 자연어로 수행하도록 전환한 Discord 기반 운영 어시스턴트

- **개발 기간**: 2026.04 – 2026.05
- **형태**: SSAFY 자율 프로젝트
- **역할**: DoitDo 백엔드 개발 · 인프라 운영 · AI 어시스턴트 설계 및 도입
- **NanoClaw Fork**: [Jaeboong/nanoclaw — doitdo branch](https://github.com/Jaeboong/nanoclaw/tree/doitdo)
- **출시**: Play Store · App Store

## 프로젝트 배경

DoitDo는 TODO를 완료하면 캐릭터가 성장하는 할 일 관리 앱입니다. 앱의 백엔드 개발과 인프라 운영에 참여하면서, 서버와 로그를 확인할 수 있는 사람이 인프라 담당자에게 집중되는 문제를 확인했습니다.

문제가 발생할 때마다 담당자가 직접 서버에 접속해 로그와 컨테이너 상태를 확인해야 했고, 테스트 환경의 데이터 확인이나 운영 정보 공유에도 담당자의 개입이 필요했습니다.

## 해결 방식

오픈소스 에이전트 런타임 NanoClaw를 fork한 뒤, DoitDo의 Discord 협업 환경과 서버 구조에 맞게 커스텀했습니다.

```text
팀원의 Discord 자연어 요청
    ↓
AI 운영 어시스턴트
    ├─ 코드베이스·프로젝트 지식
    ├─ 운영/개발 서버·Docker
    ├─ Prometheus 메트릭
    ├─ Loki 로그
    └─ Grafana 경보
```

## 주요 기능

### 자연어 기반 운영 지원

- 서버 상태, 컨테이너와 로그를 Discord에서 자연어로 확인
- 운영 서버와 개발 서버의 상태를 직접 조회한 뒤 결과 공유
- 코드베이스와 인프라 현황을 함께 참고하는 프로젝트 질의응답
- 제품·팀·서버 구조·반복 질문을 장기 지식으로 관리

### 장애 감지·분석·공유

- Grafana Alerting webhook을 NanoClaw가 수신하도록 구현
- 치명적 경보 발생 시 담당자를 호출하고 메트릭·로그·코드베이스를 함께 확인
- 원인 추정, 영향 범위와 권장 대응을 Discord 모니터링 채널에 공유
- 일간·주간·월간 요청량·오류율·지연 시간·가용성 요약 기능 구현

### 협업 도구 연결

- GitLab Push/MR webhook을 작업 흐름에 연결
- Jira 데이터와 Discord 작업 렛저를 연결해 변경 권장 사항 관리
- 운영과 모니터링 채널의 에이전트 역할을 분리

## 권한과 안전장치

- 그룹별 에이전트 컨테이너 격리
- 역할별 파일시스템 마운트와 읽기·쓰기 권한 분리
- 개발 서버 SSH 키 읽기 전용 제공
- 발신자 허용 목록과 채널별 트리거 정책
- 시크릿이 에이전트 컨테이너에 직접 노출되지 않도록 차단

## 결과

- 특정 담당자에게 집중된 운영 정보와 반복 확인 업무를 팀이 사용할 수 있는 자연어 인터페이스로 전환
- 장애 감지 → 담당자 호출 → 원인 분석 → 대응 제안 → 팀 공유를 하나의 워크플로우로 연결
- 운영 지식과 분석 결과가 팀 채널에 축적되도록 구성

정량적인 시간 절감률이나 장애 대응 시간은 별도 측정하지 않았으며, 확인되지 않은 수치는 사용하지 않습니다.
