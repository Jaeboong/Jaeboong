# 자소전 — 멀티에이전트 자기소개서 작성 지원 서비스

> 채용공고 분석부터 기업 조사, 개인 경험 연결, 초안 작성과 검토까지 하나의 AI 워크플로우로 연결한 개인 프로젝트

- **개발 기간**: 2026.04 – 진행 중
- **인원**: 1명
- **역할**: 제품·아키텍처·오케스트레이션·백엔드·인프라 전체 설계 및 구현
- **Repository**: [Jaeboong/Jasojeon](https://github.com/Jaeboong/Jasojeon)
- **Service**: [자소전.com](https://xn--9l4b13i8j.com)

## 문제

자기소개서를 작성하려면 채용공고, 기업 정보, 개인 경험과 기존 문서를 각각 찾아야 합니다. 하나의 LLM에 모든 자료와 작업을 한 번에 맡기면 사실성·직무 적합성·문장 품질을 동시에 관리하기 어렵고, 생성 도중 사용자가 사실이나 방향을 수정하기도 어렵습니다.

## 해결 방식

작성 업무를 다음 단계로 분해하고 각 단계에 역할이 다른 에이전트를 배치했습니다.

```text
채용공고 분석 → 기업 조사 → 경험 연결 → 작성 방향 설정
→ 섹션 초안 → 독립 검토 → 사용자 개입 → 최종 정리
```

### 역할 기반 오케스트레이션

- **Coordinator**: 현재 섹션의 목표, 방향과 완료 조건 정의
- **Drafter**: 계획을 실제 자기소개서 문장으로 작성
- **Reviewers**: 사실성·근거, 직무 적합성, 어조·진정성을 서로 독립적으로 검토
- **Finalizer**: 차단 의견이 없을 때 초안과 검토 결과를 최종본으로 통합

같은 라운드의 Reviewer가 서로의 결과를 보지 못하게 해 선행 의견에 동조하는 문제를 줄였습니다. 판정값과 설명을 분리해 오케스트레이터가 다음 단계 진행 여부를 안정적으로 결정하도록 구성했습니다.

### Human-in-the-loop

- 실행 중 사용자 입력이 들어오면 진행 중인 모델 호출에 중단 신호 전달
- 중단 시점의 상태와 부분 결과 저장
- 사용자 지시에 따라 기존 방향 수용, 방향 전환 또는 추가 확인으로 분기
- Drafter와 Reviewer 사이에서도 사용자 메시지를 확인해 다음 라운드에 반영

### 자료와 출처 연결

- JSON-LD·정형 데이터·HTML을 이용한 채용공고 분석
- DART 공시, 웹 자료, 채용공고를 사실·맥락·직무 요건으로 구분
- Notion MCP와 개인 경험 문서를 작성 컨텍스트로 연결
- 신뢰도가 낮은 회사명·직무 정보는 사용자 확인 전 인사이트 생성을 차단

## 시스템 구조

```text
React Web UI
    ↓ HTTP / Browser WebSocket
Fastify Backend — 인증·RPC 중계·이벤트 팬아웃
    ↓ Outbound WebSocket
Local Runner — 문서·인증정보·LLM CLI 실행
    ↓
ReviewOrchestrator — Claude / Codex / Gemini 역할 실행
```

실제 문서와 AI 인증정보는 사용자 PC의 Local Runner에 보관하고, Backend는 실행 명령과 이벤트만 중계하도록 경계를 나눴습니다.

## 검증 결과

- 공고 파서 사실 필드 인식률 **27.3% → 43.8%**
- ATS 관련 오인식 사례 **32건 → 0건**
- 개인 경험 저장소 관련 테스트 **80/80 통과**
- 사용자 개입 후 동일 실행 흐름으로 복귀하는 회귀 경로 구현

위 지표는 파서 정확성과 회귀 검증 결과이며, 합격률이나 외부 사용자 성과를 의미하지 않습니다.
