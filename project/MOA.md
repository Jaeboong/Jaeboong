# MOA — 금융 Open API 기반 목표·예산 관리 서비스

> 계좌 동기화와 소비 분석을 목표·예산·실제 소비 행동으로 연결한 금융 관리 서비스

- **개발 기간**: 2026.02.18 – 2026.03.30
- **인원**: 6명
- **역할**: 백엔드 · 계좌 동기화, 예산 배분과 자금 정합성 로직
- **Repository**: [Jaeboong/MOA](https://github.com/Jaeboong/MOA)

## 문제

금융 API의 계좌·거래 데이터와 서비스 내부 DB의 상태가 어긋나면 소비 분석, 예산과 목표 화면이 서로 다른 기준을 사용하게 됩니다. 또한 소비 내역을 보여주는 것만으로는 사용자가 다음 행동을 결정하기 어렵습니다.

## 해결 방식

```text
계좌 동기화 → 거래 분석 → 목표 계획 → 주간 예산 → 실제 소비
```

외부 금융 API를 데이터 기준점으로 삼아 계좌 상태를 통합하고, 월간 수입과 목표를 주 단위 실행 계획으로 변환했습니다.

## 담당 내용

### 계좌 데이터 정합성

- 외부 금융 API 응답으로 계좌 Map을 구성해 로컬 계좌와 비교
- 외부 데이터에서 사라진 계좌를 비활성 처리하고 정상 계좌의 상태 동기화
- 동기화 로직을 트랜잭션으로 묶어 중간 실패 시 일관성 보호
- 분석·예산·목표 기능이 동일한 계좌 기준을 사용하도록 구성

### 예산 배분

- 월간 수입을 주차별 프레임으로 정규화
- 고정비를 우선 차감한 뒤 목표 저축과 자유 소비 예산 배분
- 예산 부족 시 우선순위가 낮은 목표부터 자동 조정
- 금액 변화의 근거를 결과 객체로 전달할 수 있도록 구조화

### 실행 환경

- Spring Boot에서 금융 도메인 트랜잭션 관리
- FastAPI로 분석 기능 분리
- PostgreSQL·Docker 기반 실행 환경 구성

## 배운 점

- 금융 서비스에서는 계산식보다 데이터 기준과 동기화 시점의 일관성이 중요함을 확인
- 분석 결과를 보여주는 데서 끝내지 않고 사용자의 목표와 주간 행동으로 연결하는 흐름 설계

## 기술 스택

`Java 17` `Spring Boot` `PostgreSQL` `Redis` `FastAPI` `Docker` `SSAFY 금융 Open API`
